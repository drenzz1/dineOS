> Companion to [`ERD.md`](./ERD.md). The ERD shows relationships; this file
> documents column-level details and the migration history.

- **DBMS**: PostgreSQL (Npgsql EF Core provider)
- **DbContext**: [`backend/src/DineOS.Infrastructure/Persistence/AppDbContext.cs`](../../backend/src/DineOS.Infrastructure/Persistence/AppDbContext.cs)

## Base classes

```
BaseEntity
└── Id : bigint (identity, PK)

BaseAuditingEntity : BaseEntity
├── CreatedAt : timestamp with time zone
├── CreatedBy : text NULL
├── UpdatedAt : timestamp with time zone NULL
├── UpdatedBy : text NULL
├── DeletedAt : timestamp with time zone NULL   -- soft delete marker
└── DeletedBy : text NULL

TenantAuditingEntity : BaseAuditingEntity
└── TenantId : bigint
```

`DeletedAt` is the soft-delete marker; rows are excluded from queries via an
EF Core global query filter. The query filter on `TenantAuditingEntity`
additionally restricts rows to the current tenant unless tenant context is
unset (SuperAdmin).

Every primary key uses `GENERATED BY DEFAULT AS IDENTITY` (Npgsql identity).

## Applying migrations

The full developer workflow (start Postgres, apply, add a new migration,
inspect SQL) lives in [`docs/database-migrations.md`](../database-migrations.md).
The short version:

```bash
# Start the local Postgres (from backend/)
docker compose up postgres -d

# Apply all pending migrations
dotnet ef database update \
  --project src/DineOS.Infrastructure \
  --startup-project src/DineOS.Api
```

The API also runs `db.Database.Migrate()` on startup
(`backend/src/DineOS.Api/Program.cs`), so a fresh `docker compose up` of the
full stack will arrive at the same schema as the model snapshot.

## Verifying the running schema matches

After applying migrations, you can compare against the running database:

```bash
# Dump only the schema (no data)
docker compose exec postgres pg_dump \
  --schema-only --no-owner --no-privileges \
  -U dineos -d dineos > /tmp/dineos-schema.sql
```

The dumped tables, columns, and FKs should match
[`AppDbContextModelSnapshot.cs`](../../backend/src/DineOS.Infrastructure/Persistence/Migrations/AppDbContextModelSnapshot.cs)
exactly. If they diverge, either a migration was applied manually or the
snapshot is out of date — regenerate by adding a new migration.
